================================================================================
RESUMO DIDÁTICO DOS READMEs - ESTRUTURA DO PROJETO
================================================================================

1. CONTROLLER
   - Função: Define as rotas/navegações HTTP (GET, POST, PUT, DELETE)
   - O que faz: Recebe requisições e define os endpoints da API

2. SERVICE
   - Função: Onde acontece a lógica de negócio e operações no banco
   - O que faz: Implementa CRUD e conecta com outras partes do código
   - Importante: É aqui que a "mágica" acontece, relacionando tudo de forma fluida

3. MODEL
   - Função: Criar entidades (tabelas do banco) como classes Java
   - O que faz: Cada tabela do banco vira uma classe (ex: User.java)
   - Importante: Mapeia tabelas do banco para objetos Java

4. PERSISTENCE
   - Função: Criar a conexão com o banco de dados
   - O que faz: Configura a conexão (pode ser trabalhoso, mas é rápido seguindo a documentação)

5. REPOSITORY
   - Função: Usar recursos do JPA para acessar dados
   - Estrutura esperada:
     @Repository
     public interface EntradaRepository extends JpaRepository<Entradas, Long>{
     }
   - Importante: Manter imports e anotações corretas

6. VIEW
   - Função: Formatar como os dados serão exibidos para o usuário
   - Status: Por enquanto deixar quieto (não implementar ainda)

7. CONFIG
   - Função: Conectar com o front-end em Angular
   - Observação: Mais complicado, mas ainda fácil

8. DTOs
   - Função: Formatar como os dados serão exibidos para o usuário
   - O que faz: Define o formato de entrada/saída dos dados

================================================================================
FLUXO RESUMIDO DA ARQUITETURA
================================================================================

Controller (rotas HTTP) 
    ↓
Service (lógica/CRUD)
    ↓
Repository (JPA - acesso dados)
    ↓
Model (entidades = tabelas do banco)
    ↓
Persistence (conexão com banco)

Resumo: Controller recebe requisições → Service processa → Repository acessa dados 
→ Model representa tabelas → Persistence conecta ao banco.

================================================================================

OBJETIVO: Documentar a estrutura do banco de dados com comandos DDL.

NOTA: O esquema completo está no arquivo separado: esquema_banco.sql

O arquivo esquema_banco.sql contém:

Para executar o script SQL:
1. Abra o pgAdmin
2. Conecte ao banco de dados
3. Execute o arquivo esquema_banco.sql ou copie e cole os comandos

ESTRUTURA RESUMIDA DA TABELA usuario:
