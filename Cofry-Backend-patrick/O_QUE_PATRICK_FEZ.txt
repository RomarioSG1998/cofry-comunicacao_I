2.1. CONNECTIONFACTORY (Persistence/)
-------------------------------------
O QUE É: Classe que centraliza a conexão com o banco de dados.

O QUE FAZ:
- Define URL, usuário e senha do banco
- Fornece método getConnection() para obter conexões
- Usa JDBC puro (DriverManager)

COMO USAR:
Connection conn = ConnectionFactory.getConnection();

COMO FAZER VOCÊ TAMBÉM:
1. Crie uma classe ConnectionFactory
2. Defina as constantes (URL, USER, PASS)
3. Crie método estático getConnection()
4. Use try-catch para tratar erros

EXEMPLO:
public class ConnectionFactory {
    private static final String URL = "jdbc:postgresql://host:port/database";
    private static final String USER = "usuario";
    private static final String PASS = "senha";
    
    public static Connection getConnection() {
        try {
            return DriverManager.getConnection(URL, USER, PASS);
        } catch (SQLException e) {
            return null;
        }
    }
}

2.3. USERDAO (DAO/)
-------------------
O QUE É: Classe que faz acesso direto aos dados usando SQL.

O QUE FAZ:
- salvar(Usuario) - Insere novo usuário no banco
- buscarPorId(Usuario) - Busca usuário por ID
- buscarPorEmail(String) - Busca usuário por email (usa JPA/JPQL)

COMO FUNCIONA:
1. Usa ConnectionFactory para obter conexão
2. Cria PreparedStatement com SQL
3. Preenche parâmetros (stmt.setString, etc.)
4. Executa query (executeUpdate ou executeQuery)
5. Processa resultados (ResultSet)

COMO FAZER VOCÊ TAMBÉM:

PASSO 1: Criar método salvar
public void salvar(Usuario usuario) {
    String sql = "INSERT INTO usuario(nome, email, senha_hash, tipo_usuario) VALUES (?, ?, ?, ?)";
    
    try (Connection conn = ConnectionFactory.getConnection();
         PreparedStatement stmt = conn.prepareStatement(sql)) {
        
        stmt.setString(1, usuario.getName());
        stmt.setString(2, usuario.getEmail());
        stmt.setString(3, usuario.getPassword());
        stmt.setString(4, usuario.getTipoUser());
        
        stmt.executeUpdate();
    } catch (SQLException e) {
        System.out.println("Erro: " + e.getMessage());
    }
}

PASSO 2: Criar método buscar
public Usuario buscarPorId(Long id) {
    String sql = "SELECT * FROM usuario WHERE id_usuario = ?";
    Usuario usuario = null;
    
    try (Connection conn = ConnectionFactory.getConnection();
         PreparedStatement stmt = conn.prepareStatement(sql)) {
        
        stmt.setLong(1, id);
        ResultSet rs = stmt.executeQuery();
        
        if (rs.next()) {
            usuario = new Usuario();
            usuario.setIdUsuario(rs.getLong("id_usuario"));
            usuario.setName(rs.getString("nome"));
            usuario.setEmail(rs.getString("email"));
            usuario.setPassword(rs.getString("senha_hash"));
            usuario.setTipoUser(rs.getString("tipo_usuario"));
        }
    } catch (SQLException e) {
        System.out.println("Erro: " + e.getMessage());
    }
    
    return usuario;
}

PASSO 3: Criar método listar todos
public List<Usuario> listarTodos() {
    String sql = "SELECT * FROM usuario";
    List<Usuario> usuarios = new ArrayList<>();
    
    try (Connection conn = ConnectionFactory.getConnection();
         Statement stmt = conn.createStatement();
         ResultSet rs = stmt.executeQuery(sql)) {
        
        while (rs.next()) {
            Usuario usuario = new Usuario();
            usuario.setIdUsuario(rs.getLong("id_usuario"));
            usuario.setName(rs.getString("nome"));
            usuario.setEmail(rs.getString("email"));
            // ... preencher outros campos
            usuarios.add(usuario);
        }
    } catch (SQLException e) {
        System.out.println("Erro: " + e.getMessage());
    }
    
    return usuarios;
}

3. PADRÃO DAO vs REPOSITORY
================================================================================

DAO (Data Access Object) - O que Patrick usou:
- Acesso direto com SQL/JDBC
- Mais controle sobre queries
- Mais código manual
- Melhor para queries complexas

Repository (JPA) - Alternativa:
- Abstração maior
- Menos código
- Queries automáticas
- Melhor para CRUD simples

PATRICK ESCOLHEU: DAO com JDBC puro

6. DICAS IMPORTANTES
================================================================================

✅ SEMPRE use try-with-resources:
   try (Connection conn = ...) {
       // código
   }
   Isso fecha automaticamente a conexão.

✅ SEMPRE use PreparedStatement (não Statement):
   - Previne SQL Injection
   - Melhor performance
   - Mais seguro

✅ TRATE exceções adequadamente:
   - SQLException para erros de banco
   - Logs para debug

✅ FECHE recursos:
   - Connection, Statement, ResultSet
   - Use try-with-resources para garantir

✅ VALIDE dados antes de salvar:
   - Campos obrigatórios
   - Formato de email
   - Tamanho de strings
